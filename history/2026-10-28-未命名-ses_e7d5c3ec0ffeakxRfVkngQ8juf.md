## 1. 「用中文思考」能不能生效

AGENTS.md 是拼进系统提示的，写进去会有影响，但它是**软约束**：

- **reasoning 内容不可控**：模型内部推理用什么语言，主要由模型自己决定，很多模型训练语料以英文为主，默认就用英文思考。指令能提高中文思考的概率，但不保证。
- **不一定看得见**：部分 provider 只回传 reasoning 摘要，或者干脆不回传，你没法验证它到底用哪种语言想。
- **可能反效果**：强制中文推理有时会让推理质量略降（尤其数学/代码类任务），因为模型在英文上的推理链路更熟。

如果只是想看懂它在想什么，更实用的做法是让它**把结论用中文说清楚**，而不是规定思考语言。

## 2. token 消耗

三笔账，从大到小：

| 项目 | 影响 |
|---|---|
| 指令本身的长度 | 极小。`始终用中文思考和回复` 这句大约 15–20 token，每轮都带，可忽略 |
| 思考语言本身 | **主要成本**。同义内容，中文 token 数约为英文的 **1.3–1.8 倍**（常用汉字大多 1 token，但英文一个词也才 1.3 token 左右，信息密度差在这里）。如果你的推理 token 按输出计费，这部分成本同比例上升 |

## 思考会不会进上下文

要分两层看，很多人把这两层混在一起：

**1. 存储层：会，而且一直都在。**
OpenCode 把 reasoning 当成会话里一种独立的 part 存下来。你 `cli.json` 里的 `session.thinking: "show"` 只是**显示开关**——设为 `hide` 只是不画出来，历史照样记录。这也是为什么切换显示后旧会话的思考还能重新看到。

**2. 发送层：看 provider 适配，通常不跨轮回传。**
真正决定「下一轮请求里带不带这些思考」的是 provider 适配器，规则大致是：

- **Anthropic**：thinking block 必须在同一轮的 tool 调用链里回传（否则报错），但跨轮一般被丢弃或忽略。
- **OpenAI 系**：只回传 reasoning summary，原始 reasoning item 默认不重发。
- **DeepSeek / Gemini 等**：`reasoning_content` / thought signature 类似，多数 API 并不接受把旧思考塞回输入。

所以实际效果是：**一轮里反复调工具时思考会累积；一旦这一轮结束，它基本不再参与后续请求。** 它不会像普通对话文本那样线性堆到上下文里。

## 成本结论

- 真正花钱的是**模型生成 reasoning token 本身**，跟「回不回传」关系不大。
- 回传只在少数场景（同一轮多次工具调用）里让输入变长；这部分通常还能吃到 prompt cache，单价很低。
- 会话体积变大、触发 compaction 时，reasoning 也算在里面，但那是一次性的压缩成本。

想省钱的话，`session.thinking: hide` 没用（只是不显示）。有效的是**降低推理强度**，也就是选低 effort 的 variant，例如：

```sh
opencode run --model provider/model#low "..."
```

或在 `/models` 里选带 low/fast 变体的那个。

## 先记住这 6 个操作

| 操作 | 作用 |
|---|---|
| `@` + 文件名 | 把文件塞进上下文，支持 `@src/auth.ts#20-45` 指定行范围 |
| `!` 开头 | 直接在会话里跑 shell，输出会留在上下文里 |
| `/btw 问题` | 旁问：用当前上下文回答，但**不写入会话**，不污染后续对话 |
| `/undo` → `/redo` | 连**文件改动**一起回滚（Git 仓库内），原提示词会退回输入框让你改 |
| `Ctrl+P` | 命令面板，当前界面所有动作都能搜到 |
| `Ctrl+X` 前缀 | `M` 换模型、`A` 换 agent、`N` 新会话、`L` 会话列表、`U` 撤销、`E` 外部编辑器 |

另外两个容易被忽略的：模型跑着的时候按 **Enter** 可以中途插话改方向；`Ctrl+X` 再 Enter 是排队到这一轮结束后执行。

## 效率技巧

**1. 用 agent 分工，别一个 agent 干所有事**
内置 `build`（默认，能改能跑）、`plan`（只读，先出方案不动代码）、`explore` / `general`（子 agent，独立上下文去搜代码或跑长任务）。大改动先 `/agents` 切 plan 聊方案，再切 build 落地，能省掉大量返工。

**2. 把重复的话固化成文件**
- `.opencode/commands/review.md` → 变成 `/review 参数`，支持 `$ARGUMENTS`、`$1`，还能用 `` !`git diff` `` 把命令输出自动拼进去
- `.opencode/agents/reviewer.md` → 一个只读、指定模型的子 agent
- `.opencode/skills/<名字>/SKILL.md` → 只在相关时才加载的说明书，比塞进 AGENTS.md 省 token

这三类都是普通文本，可以提交进仓库，团队共享。

**3. 权限先收紧再放开**
无匹配规则时默认是 `ask`，但 `build` 对工作区外操作比较宽松。建议在 `opencode.json` 里显式写：

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" }
  ]
}
```

规则是「最后一条匹配的生效」，所以宽规则在前、例外在后。

**4. 脚本和 CI 里用 `opencode run`**
`opencode run --format json "..."`、`--continue` 接上次、`--file a.ts` 附文件、`--standalone` 起私有服务（CI 里 API key 不会被别的进程共用）。

**5. 换个前端继续同一个会话**
OpenCode 是客户端 / 后台服务架构：TUI、`opencode mini`、`opencode serve` 起的 Web、甚至手机浏览器（`opencode pair` 出一次性链接 + 二维码）连的是同一个后台，会话是共享的。SSH 到服务器上跑、笔记本上看，很顺。

**6. 想知道自己花了多少**
`opencode stats --cost --days 7`，按模型和项目拆开。想省钱就挑带 `#low` 变体的模型，那才是真的少 token，隐藏思考没用。

## 它的优点（以及和 Cursor / Claude Code 的差别）

- **不锁模型**：任意 provider（OpenAI、Anthropic、Google，或 `baseURL` 指向本地模型），同一件事可以按需切模型和推理强度，`model#high` / `#low` 就是干这个的。
- **终端原生**：纯键盘、无 IDE 依赖，远程开发和 SSH 场景明显比 GUI 工具舒服。
- **一切皆文件**：agent、command、skill、plugin、权限全是可版本化的配置，团队能共享同一套工作流，而不是每个人在设置界面里点一遍。
- **生态兼容**：MCP、Claude 风格的 `.claude/skills` 和 `.agents/skills` 都能直接读，迁移成本低。
- **本地优先**：会话、快照都存本地（`opencode debug paths db`），`snapshots` 默认开启，改坏了能连文件一起退回去。
- **开源**：出问题能看日志（`~/.local/share/opencode/log/opencode.log`）、能写插件改行为。
